# Rule: 消除 Stringly-Typed 与启发式文本匹配

## 核心准则
在对本项目进行任何代码修改、新增功能或重构时，必须遵守以下工程化准则：

1. **严禁在控制流中嗅探错误字符串**：
   - 禁止使用 `if err.contains("...")` 或 `if error.message.includes("...")` 作为业务逻辑判断条件；
   - 必须使用强类型错误码（Error Code）或错误枚举（Error Enum）。

2. **严禁通过名称子串推导模型类型/实体状态**：
   - 严禁通过 `id.contains("embedding")`、`id.startsWith("qwen")` 等字符串特征猜测业务类型；
   - 数据模型必须提供显式强类型字段（如 `kind: ModelKind`）。

3. **数值归一化在数据源头完成**：
   - 播放量、时间戳、文件大小等度量数值必须由后端解析为标准整型或浮点数，前端只做格式化展示，严禁前端对自然语言（如 `"10万"`）做反向正则解析。

4. **格式解析必须完整锚定**：
   - 遇到 SRT、VTT 等文件格式，严禁简单通过 `.contains("-->")` 粗暴判定时间轴，必须使用严格正则或标准词法状态机。
