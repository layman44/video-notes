# VideoNotes 产品需求文档（PRD）

| 项目 | 内容 |
| --- | --- |
| 产品名称 | VideoNotes（暂定） |
| 文档版本 | 0.1 |
| 产品阶段 | MVP 需求定义 |
| 目标平台 | Windows 10/11 x64 |
| 核心定位 | 将公开视频链接转换为本地生成的结构化 Markdown 笔记 |
| 核心约束 | 16GB 内存以内、无独立显卡、默认本地处理 |

## 1. 产品概述

VideoNotes 是一款本地优先的 Windows 桌面应用。用户输入抖音、哔哩哔哩等平台的公开视频链接后，软件获取视频元数据和音频，在本机完成语音转写、异常片段复核、内容分章和摘要整理，最后生成可编辑、可导出的 Markdown 文档。

产品不依赖平台字幕，不上传音频和转录内容，不分析视频画面。联网仅用于解析视频链接、下载音频、下载模型和检查组件更新。

## 2. 背景与问题

用户经常通过短视频、课程、访谈、播客和技术分享学习，但视频内容存在以下问题：

- 无法像文本一样快速搜索和浏览。
- 手工记录笔记耗时，容易遗漏重要信息。
- 自动摘要通常缺少可追溯的时间戳。
- 云端转写可能涉及隐私、使用额度和持续费用。
- 不同平台的链接、音频格式和访问方式不统一。
- 长视频直接交给语言模型时容易遗漏内容或产生无依据总结。

VideoNotes 通过统一的视频解析、本地语音识别、分层整理和 Markdown 导出流程解决这些问题。

## 3. 产品目标

### 3.1 MVP 目标

1. 用户无需开发环境即可通过 `Setup.exe` 安装和使用。
2. 用户粘贴一个受支持的公开视频链接后，可以完成从解析到 Markdown 导出的完整流程。
3. 语音识别和内容整理默认在本机完成。
4. 在 16GB 内存、无独立显卡的目标设备上保持界面响应，并避免频繁使用交换文件。
5. 结果包含摘要、核心要点、章节笔记、时间戳和可选完整转录。
6. 长任务支持取消、失败重试和异常退出后的恢复。
7. 模型独立下载、校验、升级和删除，不随安装包分发。

### 3.2 成功指标

- 新用户无需阅读外部安装文档即可完成模型下载和首个任务。
- 在参考硬件上，30 分钟清晰普通话视频的完整处理时间不超过视频时长。
- 重复处理相同来源时，可以直接复用转录结果，不重新下载和转写。
- 用户能够从任意核心错误状态获得明确原因和下一步操作。
- 任务执行期间，主界面保持可交互，无持续性无响应。
- 应用自身峰值内存目标不超过 7GB；空闲状态目标不超过 350MB。

参考硬件定义：支持 AVX2 的现代 6 核 12 线程 CPU、16GB 内存、SSD、无独立显卡。

## 4. 非目标与明确边界

MVP 不包含：

- OCR、关键帧提取和任何画面理解。
- 平台字幕提取；即使平台存在字幕，也仍然走音频转写。
- 直播和实时字幕。
- 登录后内容、会员内容、付费内容、私密内容和 DRM 内容。
- 绕过平台访问控制、区域限制或风控机制。
- 多说话人识别和声纹分离。
- 云端转写或云端大模型作为默认路径。
- 批量链接、播放列表和账号全量抓取。
- macOS、Linux 和移动端版本。
- 自动发布到 Obsidian、Notion 或其他知识库。
- 团队协作、账号系统、云端同步和跨设备同步。

## 5. 用户类型

### 5.1 学习型用户

通过课程、知识分享和技术教程学习，希望获得章节笔记、核心要点和可回看的时间戳。

### 5.2 内容研究用户

分析访谈、播客、行业视频或竞品内容，希望保存完整转录、观点和来源信息。

### 5.3 内容创作者

整理本人或已获授权的视频，希望获得口播稿、内容提纲和结构复盘。

### 5.4 隐私敏感用户

不希望音频、转录或生成内容被上传，希望明确控制本地数据和临时文件。

## 6. 核心原则

1. **本地优先**：转写和整理默认完全在本机运行。
2. **证据优先**：摘要和要点应关联原始转录片段与时间戳。
3. **资源有界**：重型模型顺序运行，同时只执行一个重型任务。
4. **失败可恢复**：下载、转写和整理均保存阶段性结果。
5. **错误可理解**：面向用户展示业务错误，不暴露难以理解的底层堆栈。
6. **平台可替换**：平台解析与转写、整理模块解耦。
7. **不越权**：仅处理公开、无需登录且用户有权处理的内容。

## 7. 核心用户旅程

```text
下载安装
→ 首次启动
→ 下载必需模型
→ 粘贴视频链接
→ 解析视频信息

→ 本地内容整理
→ 预览和编辑 Markdown
→ 导出文档
→ 查看历史或清理数据
```

## 9. 详细功能需求

### 9.1 安装与启动

#### 用户故事

作为新用户，我希望像安装普通 Windows 软件一样安装 VideoNotes，而不需要安装 Python、Node.js、Docker、CUDA 或命令行工具。

#### 要求

- 使用 Tauri 2 构建 Windows x64 应用。
- 使用 NSIS 生成 `VideoNotes-Setup.exe`。
- 默认按当前用户安装，不要求管理员权限。
- 主程序、ASR Worker、总结 Worker、yt-dlp、FFmpeg 和 ffprobe 随应用安装。
- 模型不包含在安装包中。
- 首次启动检查必要运行环境和数据目录可写性。
- 单实例运行；再次启动时激活已有窗口。

#### 验收标准

- 在干净的 Windows 10/11 x64 环境中可完成安装和启动。
- 用户无须手动安装开发工具或推理环境。
- 卸载时允许选择是否同时删除模型、历史和缓存。

### 9.2 模型管理

#### 用户故事

作为新用户，我希望软件说明每个模型的用途、大小和资源要求，并可靠地完成下载。

#### 模型角色

| 模型 | 默认状态 | 用途 |
| --- | --- | --- |
| Fun-ASR-Nano | 必需 | 高精度多语言语音识别与毫秒级时间戳对齐 |
| Qwen3-Embedding 0.6B | 必需 | 1024 维本地语义向量搜索与关联问答 |
| Qwen3.5 2B Q4 GGUF | 必需 | 非中文转录翻译、章节、摘要和要点整理 |

#### 要求

- 远程模型清单包含 ID、版本、文件名、下载地址、大小、SHA-256、许可证信息和最低应用版本。
- 下载使用 `.part` 文件，校验成功后原子重命名。
- 支持进度、速度、剩余时间、暂停、继续、取消和重试。
- 下载前检查磁盘空间。
- 支持更改模型目录。
- 支持从本地文件导入模型并执行同样的哈希校验。
- 模型损坏或缺失时提供修复操作。
- 未安装可选复核模型时，不阻止普通任务执行。

#### 验收标准

- 首次启动能够清晰展示模型列表和下载进度。
- 下载失败可断点续传。

### 9.3 链接解析与确认

#### 用户故事

作为用户，我希望粘贴抖音或哔哩哔哩链接后，能立即看到视频标题、时长和封面，确认无误后再开始处理。

### 9.4 音频提取与切片

#### 要求

- 优先请求可用的纯音频流，不下载视频画面。
- 通过 FFmpeg 转换为 16kHz 单声道 WAV 音频。
- 避免不必要的二次有损压缩。
- 长音频按约30分钟划分为可恢复的处理单元。
- 转码和切片过程支持取消。
- 每个临时文件均归属到具体任务目录。
- 正常完成、取消或删除任务时按用户策略清理临时文件。

### 9.5 本地语音识别

#### 默认配置

```text
引擎：Fun-ASR-Nano (SenseVoice + CTC + VAD)
模型：Fun-ASR-Nano
语言：auto
并发任务：1
词级时间戳：开启
分段时间戳：开启
VAD：开启
标点恢复：开启
CPU 线程：最多为物理核心数减 2
进程优先级：低于正常
```
- 网络中断后重新启动应用，模型下载可以继续。
- 下载内容哈希不匹配时不得标记为可用。
- 删除模型不会删除历史任务和已生成文档。

### 9.3 链接输入与平台解析

#### 用户故事

作为用户，我希望直接粘贴视频链接或平台分享文本，软件能够自动识别平台和提取 URL。

#### 要求

- 接受单个 HTTP/HTTPS 链接。
- 能从包含文字的抖音分享内容中提取 URL。
- 展开短链接并规范化最终来源地址。
- 首版支持抖音和哔哩哔哩公开、无需登录的视频。
- 解析成功后展示标题、作者、时长、封面和来源平台。
- 不读取或使用平台字幕。
- 不支持的链接不得自动交给任意 Shell 命令执行。
- 不允许通过远程 URL访问本机地址、私有网段或文件协议。

#### 验收标准

- 合法公开链接能够进入确认页面。
- 分享文本能够自动提取其中的链接。
- 无效、私密、已删除、需登录和不支持的链接得到不同错误提示。

### 9.4 音频获取与预处理

#### 用户故事

作为用户，我希望软件只下载识别所需的音频，避免浪费流量和磁盘空间。

#### 要求

- 优先请求可用的纯音频流，不下载视频画面。
- 通过 FFmpeg 转换为 Whisper 所需的 16kHz 单声道音频。
- 避免不必要的二次有损压缩。
- 长音频按约30分钟划分为可恢复的处理单元。
- 转码和切片过程支持取消。
- 每个临时文件均归属到具体任务目录。
- 正常完成、取消或删除任务时按用户策略清理临时文件。

#### 验收标准

- 不产生不必要的高清视频文件。
- 处理两小时视频时不会将完整 PCM 音频载入内存。
- 中断后可以复用已完成下载和切片结果。

### 9.5 本地语音识别

#### 用户故事

作为用户，我希望所有视频都通过本机语音识别转换成带时间戳的文字，不依赖平台字幕和云端服务。

#### 默认配置

```text
引擎：whisper.cpp
模型：Whisper Medium Q5_0
语言：auto
并发任务：1
词级时间戳：关闭
分段时间戳：开启
VAD：保守开启
CPU 线程：最多为物理核心数减 2
进程优先级：低于正常
```

#### 要求

- ASR 在独立 `asr-worker.exe` 进程中运行。
- Worker 通过 JSON Lines 输出进度、分段结果、警告和完成事件。
- 每个转录片段包含开始时间、结束时间、文本和质量指标。
- 每完成一个处理单元立即持久化，避免只在任务结尾保存。
- 从标题、简介、标签和用户词库构造热词提示。
- 用户可以选择节能、均衡和高质量配置，但默认必须适合目标硬件。
- ASR 完成后退出 Worker，确保模型内存完全释放。

#### 验收标准

- 无网络状态下，只要音频和模型已存在，即可完成转写。
- 任务取消后 Worker 在合理时间内退出。
- 程序异常退出后重新启动，可以跳过已经完成的处理单元。
- 转录结果中不存在跨任务数据混淆。

### 9.6 低质量片段检测与复核

#### 用户故事

作为用户，我希望软件自动发现明显不可靠的识别片段，并在不重跑全部音频的情况下提高质量。

#### 检测信号

- 平均置信度低于阈值。
- 重复词句或循环输出异常。
- 有效人声时长与文本长度明显不匹配。
- VAD 判断有人声但转录为空。
- 时间戳跳跃或重叠异常。
- 相邻片段内容高度重复。

#### 要求

- 已安装 Medium 模型时，只重跑命中的片段。
- 重跑范围在目标片段前后扩展 1～2 秒。
- 未安装 Medium 模型时，允许跳过并标记可疑片段。
- 不因单个复核片段失败而丢弃完整任务。
- 文档中可以选择显示低置信度提示。

#### 验收标准

- 正常片段不被整段重复处理。
- 复核结果保留原始版本，便于回退和比较。
- 未安装复核模型时，核心流程仍能完成。

### 9.7 本地内容整理

#### 用户故事

作为用户，我希望软件将长转录整理为易读的章节、摘要和核心要点，并保留事实来源。

#### 默认配置

```text
引擎：llama.cpp
模型：中文 3B～4B Q4 GGUF
上下文：4K～8K
运行方式：CPU
模式：非深度推理
```

#### 处理流程

1. Rust 对转录做确定性清洗、去重和时间段分组。
2. 按 5～10 分钟或语义边界切分内容。
3. 本地模型为每块生成结构化 JSON。
4. 程序合并相邻主题，生成章节候选。
5. 本地模型根据章节结果生成全局摘要和核心要点。
6. Rust 校验字段、时间范围和引用关系。
7. 使用模板渲染 Markdown。

#### 要求

- 总结在独立 `summary-worker.exe` 进程中运行。
- 开始整理前确认 ASR Worker 已退出。
- 模型输出先采用结构化 JSON，不直接信任自由格式 Markdown。
- 摘要、要点和章节必须能关联一个或多个转录时间范围。
- 完整转录不得被语言模型静默改写。
- 支持只重新生成摘要或章节，不重新转写。
- 总结完成后退出 Worker 并释放模型内存。

#### 验收标准

- 两小时转录不会一次性放入单个超长上下文。
- 模型输出不是有效 JSON 时能够修复、重试或降级。
- 重新生成摘要不会修改原始转录数据。

### 9.8 Markdown 预览与导出

#### 用户故事

作为用户，我希望预览、编辑并导出标准 Markdown，以便在其他笔记工具中继续使用。

#### 默认结构

```markdown
---
title: 视频标题
author: 作者名称
platform: bilibili
source: https://example.com/video
duration: 00:32:18
processed_at: 2026-08-16T12:00:00+08:00
---

# 摘要

# 核心要点

- 要点一
- 要点二

# 章节笔记

## [00:00] 背景介绍

## [05:24] 核心方法

# 完整转录

[00:00] 转录内容……
```

#### 要求

- 支持 Markdown 源码和渲染预览。
- 用户编辑内容时自动保存草稿。
- 导出时可选择是否包含完整转录、时间戳和 Front Matter。
- 默认文件名根据视频标题生成，并清理 Windows 非法字符。
- 同名文件存在时询问覆盖、另存或取消。
- 可以同时导出 `transcript.json` 作为可恢复的原始数据。
- 时间戳在平台支持的情况下生成可跳转的来源链接。

#### 验收标准

- 导出的 Markdown 使用 UTF-8 编码。
- 在常见 Markdown 编辑器中能够正常打开。
- 用户编辑内容后重新打开任务，编辑结果仍然存在。

### 9.9 任务管理、取消与恢复

#### 任务状态

```text
created
→ resolving
→ downloading
→ preprocessing
→ transcribing
→ reviewing
→ summarizing
→ rendering
→ completed
```

任意执行状态可以进入：

```text
paused | cancelling | cancelled | failed
```

#### 要求

- 界面显示当前阶段、阶段进度、整体进度和最近事件。
- 用户可以取消任何执行中的任务。
- 可恢复阶段保留 checkpoint。
- 应用启动时检查未完成任务并询问是否继续。
- 错误重试应从最近可复用阶段开始。
- MVP 同时只允许一个重型任务处于执行状态。

#### 验收标准

- 下载中取消不会继续产生网络流量。
- 转写中取消能够终止 Worker 并保存已完成结果。
- 整理失败时不要求重新下载或转写。

### 9.10 历史、缓存与数据清理

#### 要求

- 历史页展示标题、来源、状态、创建时间和最后更新时间。
- 使用规范化 URL 和音频内容哈希识别重复任务。
- 重复链接允许打开已有结果、重新整理或强制重新处理。
- 支持删除单个任务和清空历史。
- 删除任务时分别选择保留或删除导出文件。
- 支持处理完成后自动删除临时音频。
- 模型文件不随普通缓存清理而删除。

#### 验收标准

- 清理临时数据后，已导出的文档不受影响。
- 清除历史前展示将被删除的数据范围。
- 删除操作不允许使用不明确的递归路径。

## 12. 错误分类

| 错误代码 | 用户提示方向 |
| --- | --- |
| INVALID_INPUT | 未找到有效视频链接 |

| SOURCE_NOT_FOUND | 视频不存在或已删除 |
| AUTH_REQUIRED | 视频需要登录或当前无权访问 |
| ACCESS_RESTRICTED | 视频存在访问或地区限制 |
| NETWORK_INTERRUPTED | 网络中断，可继续重试 |
| AUDIO_UNAVAILABLE | 未找到可用音频流 |
| NO_SPEECH | 未检测到足够语音；当前版本不识别画面文字 |

错误界面必须包含：发生了什么、哪些数据已保存、用户可以执行什么操作。

## 13. 非功能需求

### 13.1 性能与资源

- 目标环境：16GB 内存、无独立显卡、SSD。
- 应用自身峰值内存目标不超过 7GB。
- 空闲状态目标不超过 350MB。
- 同时只加载一个推理模型。
- 同时只执行一个重型任务。
- 默认至少保留两个逻辑核心给系统和界面。
- 主 UI 线程不得执行下载、转码或推理工作。
- 长音频采用流式读取和分块处理。
- 用户操作在处理期间应在 200ms 内获得视觉反馈。

### 13.2 稳定性

- 每个主要阶段具有持久化 checkpoint。
- Worker 崩溃不能导致主应用退出。
- 临时文件写入完成前不得覆盖有效文件。
- SQLite 使用事务保证任务状态与结果一致。
- 日志应自动轮转并限制总大小。

### 13.3 隐私

- 默认不上传音频、转录和 Markdown。
- 默认不收集遥测；未来如增加必须由用户主动选择。
- 明确展示所有联网操作。
- 提供一键清理历史、缓存、音频和模型的入口。
- 敏感路径和用户内容不得写入普通诊断日志。

### 13.4 安全

- 所有外部进程参数以参数数组传递，不拼接 Shell 命令。
- 用户 URL 仅允许 HTTP/HTTPS。
- 拒绝 localhost、回环地址、链路本地地址和私有网段。
- 模型下载必须使用 HTTPS 并校验 SHA-256。
- 远程模型清单应支持签名验证。
- Sidecar 仅允许执行预先声明的二进制文件和参数范围。
- 临时文件使用应用专属、可验证的绝对路径。
- 发布版本及安装包应进行 Windows 代码签名。

### 13.5 可用性与可访问性

- 首版界面语言为简体中文。
- 核心操作支持键盘导航。
- 不能只使用颜色表达成功、警告和错误状态。
- 长任务必须持续提供进度或活动状态。
- 技术日志默认折叠，错误首先使用用户可理解的语言。

## 15. 核心验收场景

### AT-001 首次安装

在未安装 Python、Node.js、FFmpeg 和 CUDA 的 Windows 电脑上，用户通过安装包启动应用并进入模型下载向导。

### AT-002 模型断点续传

模型下载到一半时断开网络并关闭应用；恢复网络重新打开后，从已有进度继续，最终通过哈希校验。

### AT-003 普通链接完整流程

输入一个公开、无需登录的受支持视频链接，系统完成解析、音频下载、转写、整理和 Markdown 导出。

### AT-004 不使用平台字幕

对于带平台字幕的视频，任务记录显示内容来源仍为本地 ASR，不读取平台字幕文件。

### AT-005 无语音视频

输入纯音乐或无有效人声的视频，系统返回 `NO_SPEECH`，并说明当前版本不识别画面文字。

### AT-006 长任务恢复

转写长视频过程中强制关闭应用；重新打开后可以从已完成音频块继续，而不是重新下载和从头转写。

### AT-007 整理失败重试

总结 Worker 失败后，用户能够基于已有转录重新整理，不重复执行下载和 ASR。

### AT-008 重复链接缓存

再次输入已经处理的视频链接，系统提示已有结果，并提供打开结果、重新整理和强制重新处理选项。

### AT-009 资源上限

在参考硬件上处理任务期间，主界面保持响应，应用自身峰值内存不超过 7GB，且不存在 ASR 与总结模型同时驻留。

### AT-010 取消与清理

用户在下载、转写或总结阶段取消任务后，相关 Worker 停止；根据用户选择保留 checkpoint 或清理临时文件。

### AT-011 不支持与受限链接

无效、需登录、已删除和不支持平台的链接显示对应错误类型，不统一显示“未知错误”。

### AT-012 Markdown 正确性

导出文件为 UTF-8，Front Matter 合法，标题经过 Windows 文件名清理，时间戳与原始转录范围一致。

## 16. MVP 发布门槛

满足以下条件才能发布首个 MVP：

- 所有 P0 功能已完成。
- AT-001 至 AT-012 全部通过。
- 在至少两台不同 CPU 的 16GB 无独显 Windows 设备上完成性能验证。
- 抖音与哔哩哔哩各准备公开测试链接并完成回归测试。
- 安装、升级、卸载、模型下载和数据清理路径均经过测试。
- 第三方组件和模型许可证完成核对并在应用中展示。
- 安装包和可执行文件完成代码签名。
- 无已知的数据丢失、任意命令执行、目录越界删除或隐私上传问题。

## 19. 产品决策记录

| 决策 | 原因 |
| --- | --- |
| 不做 OCR | 降低计算量、复杂度和资源占用 |
| 不使用平台字幕 | 统一内容来源和识别流程，避免依赖字幕可用性 |
| 默认本地转写和整理 | 隐私、离线能力和长期成本可控 |
| 目标为 16GB 无独显设备 | 扩大可用设备范围并约束资源设计 |
| 模型安装后下载 | 缩小安装包，允许模型独立升级和删除 |
| 使用 whisper.cpp | 避免 Python 运行时，便于 Windows 原生分发 |
| 使用 llama.cpp | 支持本地 GGUF 量化模型和 CPU 推理 |
| 推理采用独立 Worker | 可靠释放内存并隔离崩溃 |
| 使用 Tauri 而非 Electron | 控制空闲内存和安装体积 |
| MVP 单任务执行 | 控制内存、CPU 和恢复复杂度 |
